# 全国碳排放数据生成方案 · 可行性分析

日期：2026-09-14
需求：数据生成服务扩展为「全国所有省+市」真实行政区划、符合各省特点的月度数据，每月自动增量生成上月数据。

---

## 一、总体结论

**可行，建议实施。** 现有生成器架构（强度矩阵 × 季节因子 × 随机波动）可直接参数化扩展到全国，主要工作量在真实数据准备与省级参数标定，预计 **3~4 天**完成。

---

## 二、数据规模测算

### 行政区划规模（真实数据）

| 层级 | 数量 | 说明 |
|---|---|---|
| 省级 | 31（大陆） | 23 省 + 4 直辖市 + 5 自治区；港澳台不纳入（无统一能源统计口径） |
| 地级 | ~333 | 293 地级市 + 7 地区 + 30 自治州 + 3 盟 |
| 直辖市辖区 | ~80 | 北京16/天津16/上海16/重庆38（区县视作"市"级） |

> 粒度建议：**省 + 市两级**（不再展开区县——全国区县 2800+ 的真实 GDP 数据难获取且数据量暴增 8 倍，市级粒度对演示与钻取已足够）。

### 数据量（按现有"24 个行业×能源组合"口径）

| 场景 | 计算 | 条数 |
|---|---|---|
| 全量初始化（5 年历史） | 333 市 × 24 组合 × 12 月 × 5 年 | **~48 万条** |
| 每月自动增量 | 333 市 × 24 组合 × 1 月 | **~8000 条** |
| 核算月度表 / 年度表 | 同上 / 333×24×5 | 48 万 / 4 万 |

**MySQL 8 完全可承受**：48 万条明细 + 聚合表 + 索引，现有 INSERT...SELECT 核算 SQL 秒级完成；前端按省/市聚合查询无压力。

## 三、真实数据方案

### 3.1 行政区划名称与代码

- **来源**：民政部行政区划代码（GB/T 2260 标准），可通过开源数据集获取（如 modood/Administrative-divisions-of-China 的 JSON），实现时整理为 SQL 种子文件（约 400 行 INSERT）
- **编码规则**：省 2 位（如 32=江苏）、市 4 位（如 3201=南京）——现有 `dim_region.region_code` 字段直接兼容
- **落库形态**：`docs/sql/regions_cn.sql`（可重复执行，替换演示省市数据）

### 3.2 各省经济能源参数（数据准确性：公开统计近似值）

每省一行参数，来自国家统计局年鉴/能源统计年鉴（公开数据，实现时内置于配置）：

| 参数 | 用途 | 来源 |
|---|---|---|
| 省 GDP、市 GDP | 活动数据规模基准 | 统计局年鉴（如 2023 年） |
| 第二产业占比 | 行业结构权重调整 | 统计局 |
| 煤炭占能源消费比重 | 能源结构权重调整 | 能源统计年鉴 |
| 单位 GDP 能耗（吨标煤/万元） | 能耗总量基准 | 能源统计年鉴 |
| 电网排放因子 | 电力核算（六大区域电网分别取值） | 生态环境部年度公告 |
| 供暖标识（北方省份） | 冬季热力季节因子 | 地理常识（秦岭淮河线） |

### 3.3 全国总量校准锚点

全国能源活动 CO2 排放约 **115 亿吨/年**（国际机构 2023 口径）——生成数据校验各省加总是否落在 100~130 亿吨区间，保证演示数据"像真的"。

## 四、各省特点建模方案（生成器改造）

现有公式：`月消费 = 区县GDP × 强度 × 季节 × 增长 × 随机`

改造为三级差异化：

| 层 | 参数 | 差异化内容 |
|---|---|---|
| 全国 | 强度矩阵（复用现有 24 组合） | 不变 |
| **省级** | 产业结构系数、煤炭占比系数、能耗强度系数、电网因子、供暖标识 | **山西煤耗高、四川水电多、内蒙古热力需求大、沿海制造业集中**等特征 |
| 市级 | 市 GDP 占省比 | 市间规模差异 |

季节因子增强：
- 南方省份：现有季节曲线
- **北方供暖省份**（约 15 省）：11~3 月热力与煤炭消费显著抬升（冬季供暖峰）
- 气温极端省份可后续再加（非必须）

电力因子改造：`factor_emission` 表拆 6 行区域电网因子（华北/东北/华东/华中/西北/南方），核算时按省份所属电网取因子（新增 `dim_region.grid_code` 字段或映射表）。

---

## 五、每月自动增量方案

- **定时任务**：每月 1 日 00:30 执行（`@Scheduled(cron = "0 30 0 1 * ?")`），生成"上月"数据并自动核算
- **首月初始化**：部署时一次性生成历史 N 年（默认 2021 至今），此后每月仅增量 ~8000 条（秒级）
- **幂等保护**：按 (region, year, month) 唯一性校验，重复执行不产生重复数据
- **参数随年份变化**：GDP 按各省实际增速（内置数组）逐年演进；未来月份数据不生成（只生成"已过完的月份"）
- 手动触发保留：`POST /data/generate` 扩展 `mode`（all 全量 / recent 补最近一个月）

## 六、现有系统改动清单

| 模块 | 改动 | 工作量 |
|---|---|---|
| 数据库 | ① 真实行政区划种子（~400 行 SQL）② 省级参数表或配置 ③ 电网因子拆 6 行 | 0.5 天 |
| 生成器 | 参数化改造（省级系数 + 供暖季节 + 增量模式 + 唯一性校验） | 1~1.5 天 |
| 核算 | 电力因子按电网取数（核算 SQL 改造） | 0.5 天 |
| 定时任务 | 每月增量生成 + 自动核算 | 0.5 天 |
| 前端 | ① 区域下拉改省-市级联 ② 大屏/分析页适配 ③ **可选**：ECharts 全国地图热力（需本地引入 GeoJSON，离线可用） | 1~1.5 天 |
| 校准 | 全国总量/各省量级校验，调参 1~2 轮 | 0.5 天 |

**合计约 3.5~4.5 天。**

## 七、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 真实数据口径不一致（不同年鉴年份） | 总量偏差 | 统一标注"演示用公开统计近似值"，用全国 115 亿吨锚点校准 |
| 参数标定后各省量级失真 | 答辩被问倒 | 校验清单：广东/江苏排放最大、西藏最小、山西煤占比最高——按常识抽查 |
| 地图 GeoJSON 版权/离线 | 演示无网络 | 使用阿里 DataV 公开 GeoJSON 存本地（演示注明来源） |
| 全国地图展示数据聚合慢 | 大屏卡顿 | 省级聚合接口已有聚合表支撑，无压力 |
| 演示库已有数据冲突 | 旧演示数据混入 | 生成器切换全国模式时清空重建，一键切换 |
| 首月后忘记重启导致不生成 | 增量缺失 | 手动"补数据"按钮 + 启动时自检提示 |

## 八、实施步骤建议

1. **数据准备**：行政区划 SQL + 省级参数表（0.5 天）
2. **生成器改造**：参数化 + 供暖季节 + 增量/全量模式（1 天）
3. **核算适配**：区域电网因子（0.5 天）
4. **定时任务与校准**：全国总量验证（0.5 天）
5. **前端适配**：省市级联 + 全国地图大屏（1~1.5 天，可分期）
