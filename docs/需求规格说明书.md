## 1 引言

### 1.1 编写目的

本说明书定义"区域碳排放大数据监测与仿真决策平台"的功能需求、性能需求、数据需求与外部接口需求，作为项目设计、开发、测试与验收的依据。预期读者：开发团队、指导教师、评审专家。

### 1.2 项目背景

"双碳"目标下，地方政府面临碳排放管理"数据分散口径不一、核算依赖人工、达峰路径不清、政策效果无法预演"四大痛点。本平台面向政府碳管理部门，提供"**监测—核算—预警—预测—仿真—决策**"一体化能力，以大数据分析与 AI 技术支撑区域碳治理决策。

### 1.3 术语与缩略语

| 术语 | 说明 |
|---|---|
| 活动数据（AD） | 能源消耗实物量（如原煤万吨、电力亿千瓦时） |
| 排放因子（EF） | 单位能源消耗产生的 CO₂ 排放量（tCO₂/t 或 tCO₂/MWh） |
| 碳强度 | 单位 GDP 的 CO₂ 排放量（tCO₂/万元） |
| 达峰进度 | 当前排放量占预测峰值排放量的百分比 |
| RAG | 检索增强生成（Retrieval-Augmented Generation） |
| LSTM | 长短期记忆神经网络，用于时间序列预测 |
| 蒙特卡洛模拟 | 基于随机抽样的不确定度分析方法 |
| 孤立森林 | 无监督异常检测算法（Isolation Forest） |
| SSE | Server-Sent Events，服务端流式推送 |

## 2 项目概述

### 2.1 产品定位与目标

面向区域（省级/市级）碳管理部门的 Web 平台，以**模拟数据 + 算法仿真**为演示形态（不含硬件与真实数据接入），构建覆盖碳数据管理、自动核算、可视化监测、智能预警、趋势预测、政策仿真与 AI 辅助决策的完整闭环。

### 2.2 目标用户

| 角色 | 说明 | 权限范围 |
|---|---|---|
| 系统管理员 | 平台运维人员/演示人员 | 全部功能，含系统配置、知识库维护 |
| 业务用户 | 政府碳管理人员 | 数据查看、分析、仿真、报告、AI 问答（不含系统配置） |

### 2.3 建设范围

**本期建设（1 个月内交付）**：

1. 数据管理模块（模拟数据生成、Excel 导入导出、排放因子库）
2. 碳核算引擎（能源活动类自动核算）
3. 可视化大屏与多维钻取分析
4. 智能预警与异常检测
5. 排放预测与情景仿真引擎
6. AI 碳管家（RAG 政策知识库问答）
7. AIGC 监测报告生成
8. 用户与权限管理

**明确不在本期范围**：真实物联网数据采集、企业在线填报与核查闭环流程、碳交易配额管理、移动端 App、三维数字孪生。

### 2.4 运行环境

| 项 | 要求 |
|---|---|
| 服务器 | Linux/Windows 均可，4 核 8G 以上（Docker 部署） |
| 客户端 | Chrome / Edge 最新版，分辨率 ≥ 1920×1080（大屏） |
| 外部服务 | DeepSeek API（AI 问答与报告生成，可降级） |

### 2.5 假设与约束

- 演示数据由系统内置**模拟数据生成器**产生，规模 50~100 万条月度记录，无真实涉密数据；
- 核算方法学本期仅覆盖**能源活动类**排放（占区域排放 80% 以上）；
- 开发周期 4 周，团队 3~4 人；
- 架构为单体 SpringBoot + 独立 Python 算法服务，**不采用微服务框架**。

## 3 总体架构

### 3.1 技术架构

```
┌─────────────────────────────────────────────────────┐
│  前端  Vue3 + TS + Element Plus + ECharts + Pinia   │
└──────────────────────┬──────────────────────────────┘
                       │ HTTP / SSE
┌──────────────────────▼──────────────────────────────┐
│  后端  SpringBoot 3 + MyBatis-Plus + Sa-Token       │
│        MySQL 8 + Redis + EasyExcel + Knife4j        │
└──────────┬────────────────────────┬─────────────────┘
           │ HTTP（内部）            │ HTTP
┌──────────▼───────────┐   ┌────────▼─────────────────┐
│  Python 算法服务      │   │  DeepSeek 大模型 API      │
│  FastAPI + PyTorch   │   │  （对话补全，流式输出）     │
│  + sklearn + numpy   │   └──────────────────────────┘
│  + sentence-         │
│  transformers(RAG)   │
└──────────────────────┘
```

- **业务与算法解耦**：核算、数据、权限由 Java 承担；预测、仿真、异常检测、RAG 检索由 Python 算法服务承担；
- **部署**：Docker Compose 一键编排 Nginx + 前端 + SpringBoot + MySQL + Redis + FastAPI。

### 4.3 M3 碳核算引擎

| 需求编号 | 需求描述 | 优先级 |
|---|---|---|
| FR-10 | 自动核算：按公式 `排放量 = 活动数据 × 排放因子 × 氧化率` 对全量数据自动计算 CO₂ 排放；按能源品种自动匹配对应因子与氧化率 | 高 |
| FR-11 | 汇总口径：支持按「区域 / 行业 / 能源品种 / 年度 / 月度」任意组合聚合，结果落库（日/月/年三级聚合表），保证大屏查询性能 | 高 |
| FR-12 | 派生指标：自动计算碳排放总量、碳强度（tCO₂/万元 GDP，GDP 数据可配置）、达峰进度、同比/环比增速 | 高 |
| FR-13 | 核算留痕：每次核算记录执行人、时间、数据范围、因子版本，结果可追溯 | 中 |
| FR-14 | 结果对比：支持任意两个区域/行业/年份的排放量、结构对比分析 | 中 |

### 4.5 M5 智能预警与异常检测

| 需求编号 | 需求描述 | 优先级 |

### 4.6 M6 预测与情景仿真

| 需求编号 | 需求描述 | 优先级 |
|---|---|---|
| FR-23 | 趋势预测：基于历史月度排放序列训练 LSTM 模型，预测未来 10 年排放轨迹，自动标注**达峰年份与峰值量** | 高 |
| FR-24 | 蒙特卡洛不确定度：对关键参数（GDP 增速、能源强度下降率）做 1000 次随机抽样模拟，输出预测轨迹的 **95% 置信区间**阴影带 | 高 |
| FR-25 | **情景仿真器**：预设三种情景（基准/低碳/强化低碳），用户可通过滑杆实时调整参数——能源结构（煤占比）、产业结构（工业占比）、技术效率（单位能耗下降率）——调整后 ≤2 秒重算并更新排放轨迹曲线 | 高 |
| FR-26 | 情景对比：多情景轨迹同图叠加对比，展示各情景的达峰年份、峰值量、累计减排量差异 | 高 |
| FR-27 | 仿真结果保存：保存参数组合与结果曲线，支持历史情景回溯 | 中 |

### 4.7 M7 AI 碳管家（RAG 知识库问答）

**RAG 处理流程**：

```
用户提问 → 问题向量化 → 知识库向量检索(Top-K)
        → 相似度过滤 → 组装提示词(问题+检索片段+引用要求)
        → DeepSeek 流式生成 → SSE 推送前端 → 对话记录落库
                                    ↓ 检索无结果
                              返回兜底话术（预置规则回答）
```

| 需求编号 | 需求描述 | 优先级 |
|---|---|---|
| FR-28 | 知识库管理：上传政策文档（PDF/Word/TXT，如碳达峰实施方案、行业核算指南）；解析后按 500 字符分块（重叠 50 字符）入库；支持文档启停用与删除 | 中 |
| FR-29 | 向量化与存储：使用 sentence-transformers（bge-small-zh-v1.5，512 维）本地生成向量，以本地文件索引存储（FAISS/numpy），**离线可用，不依赖外部向量数据库** | 中 |
| FR-30 | 检索：问题向量与知识库余弦相似度检索，取 Top-3 且相似度 ≥ 0.3 的片段 | 中 |
| FR-31 | 生成：提示词要求模型"仅依据提供的政策片段作答，并标注引用来源文件名与条款号；片段未覆盖时明确告知"；DeepSeek 流式输出经后端 SSE 转发至前端 | 中 |
| FR-32 | 对话管理：多轮会话（保留最近 8 轮上下文），会话历史可按用户查询 | 中 |
| FR-33 | 兜底策略：DeepSeek 不可用时返回预置高频问题标准答案（政策常识库），保证演示不中断 | 高 |
| FR-34 | 知识库问答记录：问答对落库，标注引用来源，管理员可查看使用情况统计 | 低 |

### 4.8 M8 AIGC 监测报告

## 6 外部接口需求

### 6.1 Python 算法服务（FastAPI，内部 HTTP）

| 接口 | 方法 | 说明 |
|---|---|---|
| /api/alg/predict | POST | 输入区域/行业历史序列，返回未来 10 年预测值、达峰年份、置信区间上下界 |
| /api/alg/simulate | POST | 输入情景参数组合，返回仿真排放轨迹（≤2s） |
| /api/alg/anomaly | POST | 输入数据批次，返回孤立森林异常点及分数 |
| /api/alg/embed | POST | 文本向量化（知识库入库与检索共用） |
| /api/alg/rag-chat | POST | RAG 问答（内部再调 DeepSeek），流式返回，经 SpringBoot SSE 转发前端 |
| /health | GET | 健康检查 |

约定：超时 30s；返回统一 JSON `{code, msg, data}`；算法服务不可用时 Java 端返回降级提示。

### 6.2 大模型 API（DeepSeek）

- 调用方式：HTTP POST，`model=deepseek-chat`，`stream=true`；
- 用途：① RAG 问答生成 ② AIGC 报告正文生成；
- 配置项：API Key、base_url 由环境变量注入，前端不可见；
- 降级：调用失败 3 次后启用 FR-33 兜底话术。
